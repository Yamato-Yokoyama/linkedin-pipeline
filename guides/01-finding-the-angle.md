# Finding the Angle: 殴り書きから「軸」を選ぶ方法

殴り書きには**情報が3-5個まとまって入っている**ことが多い。
このまま書くと「何が言いたいか分からない投稿」になる。
1投稿 = 1メッセージに絞る判断方法をまとめる。

---

## Step 1: 殴り書きから「言えること」を全部箇条書きにする

殴り書きを読み返して、**「これが言える」「これも言える」**を全部書き出す。
判断はまだしない。

例: ドイツで退学しかけた話 の殴り書きから抽出した「言えること」

- ドイツの大学評価制度の特殊さ(試験1本)
- 1回落ちると退学リスク
- 自分が初めて赤点を取った経験(感情面)
- NLP / 計算言語学が一番好きな科目だった
- 1回目と2回目で勉強法を変えた
- 暗記型 → 手を動かす型へ
- 複合語分類タスクで実装しながら学んだ
- 特徴量エンジニアリング・正規化を実際に試した
- 「初めて開発が楽しいと思えた」瞬間
- Applied Science vs Research University の違い
- ドイツ留学を考える人へのアドバイス

→ **11個の話題**が1本の殴り書きに混ざっていた

---

## Step 2: 5つの「軸」フレームから選ぶ

LinkedInで強く刺さる軸は、だいたい5パターンに分類できる。
殴り書きの中身を、どの軸でフレーミングするか決める。

### 軸A: Failure → Recovery (失敗→挽回)
- 「〇〇に失敗した。でも△△で挽回できた話」
- **強い**: 共感を呼ぶ、ストーリー性が高い
- **弱い**: 自己啓発っぽくなりやすい
- 適している殴り書き: 失敗体験 + 学び + 行動変化 がある時

### 軸B: Counter-intuitive Insight (意外な気づき)
- 「常識的には〇〇だと思われてるけど、実際は△△だった」
- **強い**: 「えっ、そうなの?」で読まれる、シェアされやすい
- **弱い**: 根拠が弱いと炎上リスク
- 適している殴り書き: 体験から得た「予想と違った」気づきがある時

### 軸C: System / Process Explainer (制度・仕組み解説)
- 「〇〇という制度を説明します」
- **強い**: 情報価値が高い、検索流入も狙える
- **弱い**: 自分の体験が薄れる、Wikipedia的になりがち
- 適している殴り書き: 体験を通じて分かった制度・ルール・構造がある時

### 軸D: Technical How-to (技術的やり方)
- 「〇〇を△△する方法」
- **強い**: 技術力が直接見える、ターゲットが明確
- **弱い**: ストーリー性が消える、似た投稿に埋もれる
- 適している殴り書き: 具体的な技術プロセスがある時

### 軸E: Provocative Question (問いかけ)
- 「〇〇って本当に△△なんだろうか?」
- **強い**: コメントが活発になる、議論を誘発
- **弱い**: 答えがないと弱く感じられる
- 適している殴り書き: 自分も答えが出ていない問いがある時

---

## Step 3: 自分の優先目標と照らして選ぶ

軸候補が複数ある時は、**今期のLinkedIn運用の優先目標**で選ぶ。

私の優先順位 (2026 spring):
1. 技術力を見せる
2. 学生からのDM獲得
3. ドイツ在住エンジニアとしての接点作り

→ **軸D(Technical) > 軸A(Failure→Recovery) > 軸C(System)** の順に強い

ただし、毎回同じ軸だと飽きられる。**月単位で軸の配分を見る**のが良い。

---

## Step 3.5: 軸が決まったら、対応するテンプレを選ぶ

軸 = 何を伝えたいか (Why)
テンプレ = どう構造化するか (How)

**順序が重要**: 軸を先に決めてから、そこに最適なテンプレを選ぶ。
逆順にすると、テンプレに合わせて内容を歪めてしまう。

### 軸 × テンプレ マッピング

| 選んだ軸 | 推奨テンプレ | 補足 |
|---|---|---|
| 軸A: Failure → Recovery | 6.Mindset / 1.Technical | 技術的失敗なら1.Technical |
| 軸B: Counter-intuitive Insight | 3.Germany×Tech / 5.Research | 留学体験なら3、論文なら5 |
| 軸C: System / Process Explainer | 3.Germany×Tech / 7.Resource | PDF配布なら7 |
| 軸D: Technical How-to | 1.Technical | 一択 |
| 軸E: Provocative Question | 6.Mindset / 5.Research | 個人的問いなら6、学術なら5 |
| ハイブリッド (例: A+D) | 主軸の方を採用 | 例: 失敗の話を技術話で語る → 3.Germany×Tech (体験ベース) |

### 迷った時の判断基準

- **読者に何をして欲しいか** → CTAから逆算する
  - DM欲しい → 1.Technical / 3.Germany×Tech
  - PDF配布 → 7.Resource
  - コメント欲しい → 5.Research / 6.Mindset
  - シェア欲しい → 3.Germany×Tech (情報価値)

- **その投稿で見せたい自分のレイヤー** で選ぶ
  - 技術力 → 1, 5
  - 体験・人柄 → 3, 4, 6
  - 仕事を作る人 → 2, 7

---

## Step 4: 残りの話題は別投稿にストック

「軸を1つに絞る」=「他の話題を捨てる」ではない。
他の話題は**Notion Inboxに別の投稿アイデアとしてストック**する。

例: ドイツで退学しかけた話 から抽出した11話題

| 話題 | 軸候補 | 投稿予定 |
|---|---|---|
| 試験1本制度の説明 | C: System | 別投稿(シリーズ化可能) |
| Applied Science vs Research U | C: System | 別投稿 |
| NLPの勉強法転換 | A+D: Failure×Tech | **今回の本命** |
| Tübingen / Cyber Valley紹介 | C: System | 別投稿(オフィスツアー素材) |
| ドイツ留学アドバイス全般 | E: Question | 別投稿(問いかけ系) |

→ **1本の殴り書きから3-5本の投稿ネタが取れる**

---

## Checklist: 軸を確定する前の最終チェック

- [ ] この軸で書いた時、Hookに使える1文が浮かぶか?
- [ ] 「結論」と「自分の体験」を両方含められるか?
- [ ] CTA(読者の行動)が自然に出せる軸か?
- [ ] 残りの話題は別投稿として記録したか?

3つ以上Yesなら書き始めて良い。
